# V2.19 成就系统规则基线（用户提供设计稿 v1.0）

来源：用户在本轮提供的《上帝的力量 V2.19 成就系统完整设计方案》，日期 2026-10-19。此文件记录设计基线，不表示仓库已实现，也不授权现在编码。实施前把逐项规则转成事件/判定用例；任何边界变化需先审阅。

## 总体规则

- 60 项，六类：学习表现12、竞技战绩10、道具收藏10、道具战术12、封神荣誉8、隐藏成就8。
- 小组独立解锁；常规成就可以赛季中达成，封神荣誉只在有效正式归档后颁发；已解锁永久保留。
- 正式答题必须有正常 A–D 选择并经过正式判定。正确作答不要求净积分增加。有效道具使用必须成功提交且消耗次数或生效；冰冻解除并取消的操作不算使用。有效攻击/防御以实际状态或积分结果为准。
- 排名按真实分数降序、同分并列；不得用数组顺序打破并列。
- 正式课堂业务事件能推进成就。手动改分、导入、历史回放、开发夹具不得伪造答题/竞技/道具进度。手动改分后重置名次基线。
- 每小组每项最多解锁一次。学习/竞技/道具事件产生赛季待归档解锁及可撤销进度；成就不加分、不提高道具概率、不解除限制。
- 隐藏成就的名称和条件默认不显示，只显示问号，解锁后揭晓；教师可选择查看隐藏条件。
- 稀有度为定性设计，不公布没有真实数据支持的获得率。
- 永久收藏、赛季进度、历史累计三类分开存储。旧存档仅对有可靠明细证明的成就补发；不能从最终积分推断过去的道具行为。

## 推荐的数据/事件契约（设计建议，未批准实现）

- 需稳定 groupUid；组名、数组索引和 groupNo 均不能作为永久身份。另需 seasonId、itemInstanceId、eventId、causationId。
- 核心事件：ROUND_SETTLED、ITEM_ACQUIRED、ITEM_USED、ITEM_HIT、DEFENSE_RESOLVED、EFFECT_APPLIED、EFFECT_EXPIRED、RANK_CHANGED、SEASON_ARCHIVED。事件仅在领域事务提交成功后发出，并附来源、前后值、对象 ID、序列和 schemaVersion。
- 命令撤销必须同时恢复可撤销赛季进度；永久历史计数只从已提交的正常业务事件更新。归档/成就授予需幂等唯一键，不能重试重复累计。
- 每个道具判定事实要来源于真实效果输出：命中数、实际 delta、防御接受/消耗、使用实例、前后排名、状态开始/结束。不能从 toast、动画或点击来推断。
- 60 项规则进独立 registry/纯判定器；成就 UI、解锁动效不能操作分数/库存。

## 尚需在设计评审确认的边界

1. 成就设计以“组”为身份，V3 AD-10 另外要求学生个人荣誉；两者并行还是本期只实现组荣誉。
2. 用户设计把跨赛季历史累计按组累计，但新增多教师/分组下同一组的 groupUid 归属期限、组删除后的保留策略未定义。
3. 学习表现“首次/历史累计”和可撤销赛季进度在封神榜之前的显示、成就通知回退动画语义需明确。
4. 有效赛季4组/5次答题写为建议；是否把它作为全部封神荣誉正式门槛需用户确认。
5. 并列冠军规则标“建议”；需确认是否替代现有排名算法仅用于荣誉，还是与最终档案名次同一口径。
6. ACH-012：答错后的“接下来的3个正式回合全部正确”期间漏答的语义、第二次答错是否重启窗口需进一步规格化；按原文暂不擅自解释。
7. ACH-020 的连续 All In 成功是否要求三个回合都有作答、每个都开启 All In，原文已注明无漏答/失败；正式判题事件需能区分未答回合。
8. ACH-031、034、036、039、043、044、056、058 依赖稳定实例 ID 和状态生命周期；旧历史无法可靠重构。
9. 手动改分重置排名基线的范围是“受影响组自身”和“全场基线”；设计要求防误判，但实现前需明确重置所有参赛组观察点。

## 当前仓库差异

在 HTML 当前开发 HEAD 对 src/ 做的关键词检查仅找到首页“历史荣誉”卡片/封神榜展示，没有成就注册表、计数器、解锁、持久化字段或成就页。故这是 V3 新增功能规格，不是现有可回归功能。不得伪称旧存档已经包含成就，迁移后应把旧来源标为“启用成就统计前”。
