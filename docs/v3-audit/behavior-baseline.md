### 关键联动不能拆坏

- 抽取流程与使用流程为两个可配置管线；首轮举手专池、榜首喇叭的特殊概率、抽取权重、持有道具排除、防重复、冷却提交均是抽取侧规则。
- 目标有效性由实际排名、可攻击组、分数非负等条件决定；炸弹只计实际存在邻组；空目标按每个蓝图的 allowEmpty 约定。
- 防御队列区分普通壳、刺龟壳、闪电和持续状态；命中、防御接受、消耗和积分变化需要一个原子事件结果。
- 三重物品、花类、自定义 charges 和冷却依赖库存对象字段；以后增加 itemInstanceId 必须迁移旧数据，不可把相同 key 的两件物品进度拼成同一件。
- 动画、toast、音效由已成功业务事件驱动；其失败不更改积分/库存。
- 既有记录称默认道具/防御差分464项、seeded抽取448项、基础oracle26项通过；属历史证据，未在本轮重跑。

## 成就规则基线

本轮新增用户提供的 achievement-spec.md 记录 60 项具体条件。其当前仓库差异是“未实现”，不能作为现有程序回归通过项。60项明细、学季/永久区分及9种事件契约见该文件。其关键行为约束是：

1. 组是解锁实体；需增加稳定 groupUid，不能绑定可能重排/改名/重建的 groupNo/name。
2. 有效进度须来自提交成功的业务事件，支持命令撤销回滚；季末档案成功后转永久奖励且归档幂等。
3. 不能用最后分数猜过去的攻击、防御、连续答题、All In或三连物品使用。
4. 手动改分、导入、撤销重播和测试夹具均不能伪造正向成就事件。
5. 设计的60项是业务规则，不包括 AD-10 所述学生个人荣誉；个人荣誉单独列为待设计依赖。

## 成就系统实现缺口

- 当前源码中未找到 achievement registry、事件 consumer、进度字段、解锁记录、成就视图或题库/档案迁移。
- 用户提供的条件可用作新功能基线，但6项边界尚待裁定，见 achievement-spec.md。
- 不把成就版本/业务 schema 冒充当前 schemaVersion 1；V3需单独决策成就schema。
